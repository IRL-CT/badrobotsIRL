**Units.** The paper's primary metric is second-level macro-F1 (model rows within one second reduced by majority vote), mean over five participant-disjoint folds. The relative-feature arm scores one unit per *window* (5 s, stride 2 s for the published best runs; ~330 windows over 24 participants), and the paper reports its pooled value; this report does the same. Where a number is pooled over folds rather than fold-averaged it is marked *pooled*.

## Executive summary — effect on the paper's claims

1. **Recovery (§5.2, Tables 3, 5, 6): unchanged and strengthened.** The exact best binary recovery model reproduces (F1 0.725 vs 0.735) and yields the same delay picture as the two weaker retrained models: 22/24 participants cross at k = 3, median delay 5 s, 47 % of recovery seconds still classified as error. Treating never-crossers as censored moves medians by ≤ 1 s. SMOTE off: ΔF1 −0.007.

2. **Detection representation (§5.1, Table 2): unchanged.** No new run touches Table 2; SMOTE on/off deltas for the headline configs are within ±0.02 (−0.03 for stage), inside fold SD.

3. **Relative features (§5.3, Table 4, Table 5, abstract, §1, §6, §7): the stage half holds and is now better supported; the detection half (0.959) does not hold as a behavioral finding and should be re-scoped or removed.** On a fully matched pipeline the absolute-state stage model reaches 0.458 and the relative one 0.618–0.620 (+0.16; the paper's 'half smoothing, half framing' reading is wrong — it is all framing, since 0.458 ≈ Table 2's 0.469). The gain is behavioral (labels shifted within session → 0.25, chance; noise → 0.34), survives within-phase shuffling and a 5 s unknown onset, and persists over the absolute model at every onset uncertainty (+0.21, +0.21, +0.11 for known / ≤5 s / ≤10 s). It comes entirely from Δprev + drift; Δbase adds nothing for stage. For detection, current-only gives 0.676, Δprev + drift 0.673 and adding Δbase 0.959: the whole gain is the own-baseline term anchored to a session start the protocol guarantees is pre-failure, and the advantage over the absolute model shrinks from +0.28 to +0.10 (≤5 s) to +0.04 (≤10 s).

4. **Two factual corrections to Table 5** (found while reproducing, independent of any new run): the best relative detection run is acoustic-only (25 eGeMAPS features; its W&B modality is `audio`), not 'A+G768'; and the best stage run's baseline is the first 5 s window, not '2 s', because `escalation_linear.py` converts `baseline_sec` to windows (`baseline_sec // stride_sec`, so b = 2 and b = 3 both mean one 5 s window at stride 2).

5. **One definitional note for Table 4.** Its noise column is the best of ~1,000 noise runs in the sweep (0.703 / 0.343), i.e., a best-of-search number like the real column. A single matched noise run for the published configs scores 0.456 (detection) and 0.337 (stage); the paper's Δ is therefore conservative, not inflated.

## T2 — Temporal confound: relative/drift features as a pseudo-clock; noise control too weak

**Reviewers:** 1AC; R1; R2. **Effort (sheet):** M (1–2 days incl. analysis).

**What is asked:** A control that separates elapsed time / phase base rates from behavior: within-phase window shuffle, phase-duration warping, within-participant feature–label shift, or time-block permutation.

### Evidence A — what already existed

* *Noise control* (paper Table 4): features replaced by Gaussian noise with sessions, windows, labels and folds unchanged; best noise run 0.703 (detection) / 0.343 (stage) vs real 0.959 / 0.631.
* *Elapsed-time-only baseline* (`elapsed_time_baseline.py`, not in the paper): logistic regression on seconds-since-start alone reaches F1 0.976 / AUC 0.999 for detection and 0.876 / 0.959 for error-vs-recovery, i.e., the clock beats every model. This is a property of any fixed-script study and should be stated plainly.
* *Time-matched evaluation* (`time_matched_eval.py`, not in the paper): scoring only in seconds where both classes occur across participants. Detection collapses (only 5 such seconds; AUC 0.57–0.71, CIs span 0.5); recovery survives (19 mixed seconds; AUC 0.69 engineered, 0.77 with embedding; AUC conditioned on the exact second 0.70 / 0.78). Files: `training/analysis/time_matched_v4_detection.csv`, `time_matched_v5_recovery_binary.csv`.

### Reading

* **The stage signal is behavioral.** With real features but labels cyclically shifted within each session (phase lengths and order preserved), F1 falls to 0.25 — chance for four classes — below even the Gaussian-noise control (0.34, which still sees the structural cue that early windows have small deltas). A model exploiting phase base rates or elapsed time would score well above chance here; it does not.
* **Within-phase order does not matter** (phase shuffle −0.03 for stage): the relative features read a phase-level behavioral state, not a fine-grained within-phase trajectory. R1's prediction was that the drift features would lose efficacy; they do not, which argues against a pseudo-clock reading but also means the features are not capturing escalation *within* an error instance.
* **Stage survives an uncertain onset and keeps its margin over absolute state.** Known onset 0.618 vs 0.458; onset unknown within 5 s 0.597 vs 0.391; within 10 s 0.457 vs 0.349. The 10 s drop is shared by the absolute model (the survey class largely disappears), so it reflects the test set, not the relative framing.
* **Detection is a different story.** The published 0.959 is entirely the Δbase term (Evidence B of T1) and depends on the first seconds being pre-failure: with the onset unknown within 5 s it falls to 0.717 (absolute 0.619), within 10 s to 0.575 (absolute 0.535), close to the label-shift floor (0.567). The within-phase shuffle also costs it 0.20. The honest description is 'given a baseline window known to precede the first failure, deviation from it flags the error at F1 ≈ 0.96'.

## T3 — SMOTE on windowed time series

### Facts about the pipeline (verified in code)

* Order of operations in every window-level script (`temp_allscripts/*_model.py`, `recovery/*_model.py`): load 100 fps frames → sliding-window aggregation (`apply_windowing`) → participant-level split (`create_data_splits`) → SMOTE on the **training fold's window-level rows only** → fit. Validation and test rows are never resampled. SMOTE therefore interpolates between aggregated window vectors of training participants, not between raw adjacent frames; `k_neighbors = min(5, n_minority − 1)`, `random_state = 42`.
* SMOTE is used only by the window-level classifiers (RF, SGD, SVM, MLP, k-NN). The sequence models (GRU, LSTM, Transformer) use no resampling. The relative-feature arm (`escalation_linear.py`, Table 4 / Table 5 stage and relative rows) uses **no SMOTE**: the random forest uses `class_weight='balanced'`, logistic regression / SGD / MLP are unweighted.
